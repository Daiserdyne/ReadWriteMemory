CreateOrResumeCodeCave(MemoryAddress, ReadOnlySpan<Byte>, Int32, Int32, UInt32)

Creates a code cave to apply custom code in target process. If you created a code cave in the past with the same memory address, it will jump back to your cave address.

public CodeCaveTable CreateOrResumeCodeCave(MemoryAddress memoryAddress, ReadOnlySpan<byte> caveCode, int amountOfOpcodesToReplace, int totalAmountOfOpcodesToReplace, uint memoryToAllocate)

Parameters

memoryAddress MemoryAddress
Address, module name and offsets

caveCode ReadOnlySpan<Byte>
The opcodes to write in the code cave

amountOfOpcodesToReplace Int32
The number of bytes of the instruction you want to override/create am jump instruction

totalAmountOfOpcodesToReplace Int32
Because a x64 jump is 14 bytes large, it will override other instructions, so you have to have at least 14 bytes. That means you need to give the next instruction in a whole. For example: You have a function with 7 bytes, and the next instruction has 4 and the next also 4. That means you have 15. They get copied in the cave as well since we don't do relative jumps. That's a bit weird, I know, but with that I save the search of a free space in memory in the near.

memoryToAllocate UInt32
size of the allocated region

Returns

CodeCaveTable
Cave address

Remarks:

Please ensure that you use the proper replaceCount if you replace halfway in an instruction you may cause bad things

PauseOpenedCodeCave(MemoryAddress)

Restores the original opcodes to the memory address without deallocate the memory. So your code-bytes stay in the memory at the cave address. The advantage is that you don't have to create a new code cave which costs time. You can simply jump to the cave address or use the original code. Don't forget to dispose the memory object when you exit the application. Otherwise, the codecave continue to live forever.

public bool PauseOpenedCodeCave(MemoryAddress memoryAddress)

ReplaceBytes(MemoryAddress, ReadOnlySpan<Byte>)

Basically the same as RwMemory.WriteBytes(MemoryAddress, ReadOnlySpan<Byte>) with the difference, that the original opcodes will be saved internally. So you don't have to save the original opcodes somewhere. Just call RwMemory.UndoReplaceBytes(MemoryAddress) to restore the original opcodes.
